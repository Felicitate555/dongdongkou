# 动动口 · 项目交接说明

更新：2026-09-29。当前产品事实以本说明、[README](../README.md)、[产品约定](../PRODUCT.md)、[部署手册](部署手册.md)和现行实施计划为准；旧版体验报告和 9 月 18 日计划仅保留为历史记录。

## 产品与主线

动动口面向手部操作困难的人群，用本机摄像头追踪头部并移动自由光标，再通过短促张嘴或语音操作。指针到达目标后可直接点击；不要求吸附、停留或先选中目标。语音按序选择目标是可选辅助。

两条比赛演示主线同等重要：

- **本机完整控制**：用户明确开启后，可以操作运行服务的电脑。默认关闭，服务默认只监听 `127.0.0.1`。
- **公网网页演示**：访客可以操作动动口当前网页。服务端强制禁用宿主电脑的鼠标和键盘 API，环境变量无法绕过。

资讯、购物、预约都是模拟流程，不产生真实订单、支付或医疗预约，也没有官方天猫系统接入。演示台 AI 首先展示当前页面控件结构图；用户同意后才提交。该图不含摄像头画面和输入框填写值。

## 启动和检查

本机开发：

```bat
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

浏览器打开 `http://127.0.0.1:8787`。默认是网页内控制。需要本机系统控制时，显式设置后重启：

```bat
set DDK_DEPLOYMENT_MODE=local
set DDK_SYSTEM_CONTROL=1
python run.py
```

公网容器用 `docker compose up -d --build`。Compose 绑定 `127.0.0.1:8787`，由 Nginx HTTPS 反向代理。部署说明见 `docs/部署手册.md`。

## 关键行为与安全边界

- `GET /api/health` 回报部署模式、系统控制开关、模型和屏幕信息。
- `/api/mouse/*` 与 `/api/keyboard/*` 仅在本机模式并显式开启时允许。
- 摄像头画面由浏览器中的 MediaPipe 本地处理。
- MiMo API key 通过 `QWEN_API_KEY` 环境变量读取；该变量名是历史兼容名。不要把密钥复制到源码、文档、镜像或 Compose 文件。`server/local_secrets.py` 只供本机开发并由 Docker 构建上下文排除。
- 本地 AI 回退只做控件图中的形状检测，不提供语义理解。
- 公网 AI 接口有图像体积上限和进程内请求限流；多 worker/多实例需要共享限流存储，并在代理层限流。

## 页面更改约束

- 保持两种部署模式同等清晰；不能让公网页面暗示可控制访问者电脑。
- 直接点击保持自由指针语义；目标收集仅服务于可选的语音序号等便利功能。
- 修改头姿映射、MediaPipe 生命周期或鼠标坐标映射时，检查资源清理和真实设备高 DPI/多屏差异；当前自动化检查不能代替真机体验。
- 保留 FastAPI + 原生 HTML/CSS/ES Modules 结构，不引入必须构建的前端工程。
- 页面文案必须区分真实能力、模拟数据和实验性回退路径。
