# 动动口：体验审视与录制交接

## 以行动受限用户场景推演

值得保留：直接转头移动、短张嘴点击和长张嘴拖动，减少精确用手的负担；用户已确认当前映射好用，并确认本机后台取中后可控制其他软件。本次未更改已经认可的 cursor-controller.js 与 face-tracker.js 映射。

原来的主要问题：摄像头和调试数值占据注意力，真正需要的助手藏得深；离开窗口就停，无法完成跨软件任务；说话本身会引发张嘴误点；登录、保存和恢复会话缺失；入口及技术状态不像面向日常使用者的应用。

已修改：摄像头保留在中间，左栏稍加宽，操作在上、口动助手在下；底部一个齿轮收纳手感和滚动；首页保留布局，右上角登录/注册，移除后端状态和无效链接；生活演示与说明页统一导航、色彩和全站助手。摄像头/对话可移入置顶画中画。截图先预览、再发送；说“看一下屏幕”后可说“确认”。语音发起的普通对话会在朗读结束后继续聆听；暂停、失焦或关闭悬浮会停止聆听。说话期间暂停张嘴点击，并等待闭嘴后重新启用。

这属于场景分析及单人体验反馈，不代表已完成多名不同障碍用户的研究。

## 录制建议（约两分钟）

1. 首页 → 开始使用，展示简洁的左侧助手与中间预览。
2. 自然平视取中，转头移动、短张嘴点击、长张嘴拖动。
3. 后台控制电脑 → 切到记事本，展示系统指针继续移动。
4. 打开“悬浮”，展示实时摄像头与口动助手；主动截图、检查预览后发送，让助手概括页面并朗读。避免录入密码、联系方式或其他私密信息。
5. 登录后刷新恢复文字对话（个人账号由用户自己创建）；再展示暂停/持续闭眼退出。

## 已验证与仍需本人验收

- 临时数据库中核对注册、登录恢复、账号隔离、游客不落库、退出失效、清空对话、跨站请求拒绝。
- 真实 MiMo 对话及虚构页面截图分析已返回正确标题和三个入口，截图不写数据库。
- 浏览器实际打开悬浮窗并完成一次对话，关闭后会话回到左栏。
- 用户已确认后台控制能取中并跨应用运行；本机日志观察到持续闭眼停止。
- 悬浮窗内的真实摄像头预览、连续语音识别/朗读、全局 Esc 与实体鼠标接管的最终组合，请在录制前本人走一遍。未宣称已覆盖所有设备或软件。

## 后续真正值得做的事情

一键安装本机版、记住个人动作参数、低体力用户可选输入动作、账号找回与本机/公网账号同步，比增加更多指标和装饰更有价值。当前本机与公网账号分别保存；游客仅页面内存对话。普通聊天看不到屏幕，须主动提供截图；不自动执行模型生成的系统命令。
